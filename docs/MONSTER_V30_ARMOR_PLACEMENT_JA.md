# Monster Quest v3.0 — AIアーマー配置エディター

## 機能の目的

AIで生成した角・翼・装甲の画像は、素体の形によって装着位置・大きさが合わない場合がある。v2.9までの位置ボタンは、押すたびに捕獲モンスターの保存データを書き換えていた。v3.0は**非破壊プレビュー→明示的な保存**へ統一する。

## 操作フロー

**すでに装着したパーツを調整する場合**

1. モンスター研究所で仲間と装着済み部位を選ぶ。
2. 「完成形を見て位置・大きさを調整」を開く。
3. 本編用64×64画像を確認しながら、横・縦各±12px、1px単位で移動。サイズは50〜150%・5%単位で変更。
4. 「この配置を保存」で装着済みの画像IDはそのままに、パーツの位置・大きさを一括保存。「キャンセル」では一切変更されない。

**新規AI生成・画像取り込み・ライブラリ再利用パーツ**

1. 選んだパーツの画像IDを一時的に参照して64×64完成形を表示。
2. 確認ダイアログで同じ1px／5%の調整を行う。ゲームの保存データはここでは変更されない。
3. 「この画像を装着」を選ぶと、パーツ画像IDと調整値を同時に保存し、Glyph用13×13画像も同じ完成形から再計算。
4. 「キャンセル」の場合、生成/取り込みした未採用の画像は破棄する。既存ライブラリから選んだ画像は削除しない。

**進化・融合**

- 解放前の部位は対象進化段階の完成予想を表示する。実際の進化状態やステータスは変化しない。
- 装着済み画像と個体ごとの調整値は従来のJSON保存に引き継がれる。
- 合成では親Aの頭・胸・肩、親Bの尾・背・翼とその配置値を継承する。元のPNGファイル自体は変更しない。

## 技術・検証

- 純粋関数 `ArmorPlacementDraft.withAsset` と `reposition` によってプレビュー/確定のデータ構造を統一。
- 色数16以下の64×64スプライトと、Glyph用13×13の派生画像を保つ。
- unit testは、プレビューと保存後のピクセル一致、原本画像不変、同一パーツ共有、異常なアセットID拒否、進化前プレビューの非破壊性、融合継承を確認。
- モデルの実際の生成品質、Google Geminiへの外部通信、Nothing Phone (4a) Proの実機操作は**未確認**。CIビルドと単体テストを実機試験と混同しない。
