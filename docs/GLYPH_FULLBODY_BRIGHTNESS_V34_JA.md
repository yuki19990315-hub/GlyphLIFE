# GlyphLIFE / Monster Quest — 全身ドット絵をLED輝度に変換する v3.4 / v0.15

## 背景と原則
Nothing Phone (4a) ProのGlyph Matrixは論理13×13、物理137点。従来はモンスターの全身を二値化するか、ライゼル／ルナだけ顔シンボルへ置換していた。これは**全身を表示し、LEDの明るさで階調を表現したい**という方針と矛盾するため廃止。

**本編64×64（装備・画像持込・進化・アニメを反映済み）を唯一の入力**とする。顔への置換、種族ごとの例外、端の切り取りを行わない。

## 実装した処理
1. アルファがある全身画素の外接矩形を取得し、中心を保って13×13の円形LED枠へ入れる。最大11セル相当から開始し、円の外へ出る場合は最大9セル相当まで縮小。
2. 元画素を小さいLED区画へ面積配分し、平均RGB輝度（0.2126R / 0.7152G / 0.0722B）と描画密度を両方保持。**太さのない角・脚・尾は完全な1bitに落とさず、低い輝度として残す。**
3. ガンマ0.85・コントラスト1.15で補正し、LEDごとに0〜255で出力。物理LEDがない32区画は0。これらの値はソフトウェアの意図値であり、物理的に256段階が識別できると保証するものではない。
4. GlyphLIFEへの連携JSONは旧schemaVersion=1の `pixels`（169文字の0/1）を残しつつ、任意の `levelsHex`（169個の2桁16進数＝338文字）を追加。古いアプリは従来の白黒表示、新版は連続輝度を使う。
5. GlyphLIFEの `GlyphFrame.levels` に明度を保持。保存・読込・ギャラリー・アニメで維持。手動ドット編集したフレームだけは階調情報を解除して旧来の白黒編集へ移る。
6. Nothing公式SDKの画像ソースへ13×13 RGB同値（グレースケール）Bitmapを与え、全体輝度255で `setAppMatrixFrame` 表示。端末接続を待つ間も最新フレームを保持する。
7. 工房と戦闘中のプレビューを円形配置の階調LEDに変更。CIに10体型の本編64×64とLED変換結果を並べた実描画PNGを追加。

## 互換性・制限
- 既存の手描きGlyph作品、0/1のアニメ、旧キャラクター・セーブデータは維持。
- Monster Questはv3.4、GlyphLIFEはv0.15。**両アプリを更新しなければ輝度は実機に届かない**。
- 通常のCIデバッグAPKはNothing SDKなしのスタブ版で、プレビューはできるが**実物のLEDを点灯できない**。公式SDK込みの実機ビルドは別途WindowsスクリプトまたはCIのSDKコンパイルジョブで実施する。CIのSDK専用ビルドは配布していない。
- 実機の明るさ補正・眩しさ・設定との相互作用は未確認。
- 本編の全モンスターに手描きの64×64個別イラストを用意したわけではない。ほかの種族は汎用骨格が残る。
- 13×13は物理的制約が大きく、小さな装飾や顔の細部は消える可能性がある。**顔を表示するのではなく全身を縮小している**ことと、判別性の保証は別である。

## 回帰試験
- `FullBodyGlyphProjectorTest`：3段階の違い、入力全身と二値互換、円形マスク外0、濃淡の差、空画像・無光度、安全な全体型処理
- `QuestProtocolTest`：169区画の階調をロスなく転送し、旧形式は変更しない
- `GlyphBrightnessCodecTest`：形式の厳格検証・往復・手動編集時のみ輝度解除
- `MonsterPixelPreviewTest`：`13-full-body-10-types-grayscale.png`、`11-full-body-grayscale.png`
