# Monster Quest v2.8 — 実物の素体を参照するAIアーマー生成

## 変更内容

v2.7ではAIへモンスター名・属性・骨格・スロット名だけを渡し、独立した64×64装備パーツを提案させていた。v2.8では**端末で実際に表示する現在のモンスターの絵**を一緒に渡す。

1. プレイヤーが捕獲した仲間を選び、装備スロットで「素体を見せてAIパーツ生成」を押す。
2. アプリが現在の装備を含む64×64スプライトを描画し、512×512へ補間なしで8倍拡大。透明部分は暗色背景に置き、PNGを端末内メモリで作る。
3. 画像と「指定スロットに合うパーツだけを描く。素体は再現しない」という指示をGemini画像モデルへ送信する。APIキーは利用者の入力したもの。
4. 応答の画像データを既存のCustomArmorLayers.normalizeで透過・縮小。画像の端4隅が透過またはマゼンタ背景でなければ拒否。
5. 保存した装備PNGを素体に重ねた**完成予想**を表示し、承認時のみ捕獲モンスターの装備参照を保存。キャンセル時は一時PNGを破棄。
6. 進化によるスロット解放、融合時の画像ID継承、64×64 PNG、256×256表示、13×13 Glyph出力は既存の同一spriteForパイプラインを利用する。

## アート仕様

- AIが描くのは**頭・胸コア・尾・肩・背・翼**のうち選択した**1パーツ**のみ。
- 素体の骨格・姿勢・色味を参考にしつつ、完成イラストや背景の描画を禁止する。
- アプリが装着場所を固定し、外部AIには任意座標やゲーム内能力値を選ばせない。
- 元素材は64×64、装備画像は別レイヤーとして端末内に保存。合成時も元レイヤーは書き換えない。
- Googleのモデルが常に指示どおりの透過パーツを返す保証はないため、結果画像の自動検証とユーザー確認を組み合わせる。

## 個人情報・料金・検証

- AIボタンを明示的に押したときだけ、**今選んでいるモンスターの現在の画面用スプライト**を外部サービスへ送信する。写真ギャラリーの原本や他の仲間のファイルは自動送信しない。
- ただし、**そのモンスターの表示にユーザーが取り込んだ画像の内容が含まれる場合、その内容はスプライト化された参考画像に映り得る**。送信はユーザーの意思で行う。
- ユーザー自身のGemini APIキーと利用枠が必要。画像生成は有料になる場合がある。実費はモデル・プランによって変動するため固定の価格を保証しない。
- 外部APIへの実通信、生成画像の仕上がり、Nothing Phone実機の操作は未検証。
- JVM単体テストでは、生成リクエストがテキスト＋PNG画像の2パートであり、PNG以外・過大画像を拒否することを確認する。
