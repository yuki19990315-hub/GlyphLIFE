# モンスターデザイン依頼テンプレ / GlyphLIFE

## 最新の必須基準（2026-11-13更新）
- **ゲームボーイアドバンス風のオリジナルモンスター**。既存ゲームのキャラクターの複製ではなく、シルエットと進化の読みやすさを参考にする。
- **本体の基本キャンバスは64×64ピクセル**。1ドット＝実際の画像グリッド1セル。表示拡大は最近傍補間（整数倍）とし、擬似的な高解像度イラストをそのまま「64pxドット絵」と呼ばない。
- **色数は透過色を含めて最大16色**。つまり、透明1色＋不透明最大15色。輪郭・陰影・属性アクセントの色を優先する。ARGBの中間透過は最終素材に残さない。
- **透明背景、全身、見切れなし**。角・翼・脚・尾の先まで64×64内に収め、原則キャンバスの外縁1px以上を空ける。
- 個性のある顔と骨格を最初に設計。仮の丸・楕円のつぎはぎを完成形として採用しない。
- 同じモンスターの進化1→2→3は、顔の核、属性器官、基本配色を継承しながら装甲・体格・役割が成長する。
- 本編の64×64全身を正本とし、Glyphは**同じ全身**を13×13の物理137LEDへ光度階調で投影。顔だけへの自動置換は禁止。
- 待機・攻撃アニメはそれぞれ**最低4コマ**を基準とし、元の64×64画像を加工する。Glyph向けにまず13×13を描く方式にはしない。
- 画像生成コンセプト、64pxの実スプライト、256px整数倍表示、13×13 Glyph投影の順に**別々に品質確認**する。

**実装範囲：** v3.6では色数上限・透過・全身検査と4コマ攻撃をコード側に反映。輪郭の魅力、パーツ分離、すべての種族の固有描き下ろしは自動では保証できず、現時点ではライゼルとルナの2系統のみ固有画像を持つ。

## 目的
丸・楕円・単純な図形だけを重ねて「完成デザイン」としない。モンスター収集・育成ゲームとして、**個性的な全身シルエット、魅力のある表情、体型、装甲や属性器官、進化のつながり**を最優先する。ポケモンの「誰でも分かる読みやすい造形」とデジモンの「複雑な装甲・派手な進化の迫力」を一般的な表現技法として参考にし、既存IPの固有キャラクターや特徴的意匠は複製しない。

### 依頼テンプレ（1系統につき）
- **種族名**：
- **属性**：火・水・草・雷・光・闇、その他
- **体型**：BEAST / DRAGON / BIPED / GOLEM / SERPENT / AVIAN / INSECTOID / AQUATIC / MECHA / SPIRIT
- **主・副モチーフ**：動物、自然物、機械、鉱石、天体などの組み合わせ
- **成長・性格**：幼体→成体→上位体。各段階に残す顔の核・主色・シルエット・属性器官を指定
- **見た目に必須の特徴**：頭、目、口、耳、角、胴体、手足、翼、尾、装甲、模様を具体的に
- **64×64で残す特徴**：全身を見せ、余白を保つ。端が切れない。3/4視点の原則右向き
- **カラー**：各64×64画像は透過PNG、最大16色（**透過1色＋不透明最大15色**）、明暗と輪郭が読み取れる配色
- **256×256の図鑑原画**：64×64からの単なる引き伸ばしではなく可能なら独立した高精細ドット絵。難しい場合は単なる4倍拡大と明記する
- **パーツ分離**：今後頭・胴体・腕・脚・角・翼・尾・装甲を独立透過レイヤーに分割できる構図
- **Glyph変換**：Phone (4a) Proの13×13／137物理LEDに**全身**を縮小する。顔だけ切り取らない。LEDごとの光度でモノクロ階調化
- **アニメ**：待機・攻撃を各4コマ以上。頭/尾/翼/肢体が自然に動く余地を持たせる（現在は簡易フレーム加工であり自然な部位アニメは未実装）
- **品質検査**：生成元全身→64×64→256×256→Glyphを比較し、パーツの見切れ、目と顔の可読性、細部の潰れを確認する

3. 光輪と羽状の霊衣を持つ上位の光の守護者。ライゼルと輪郭を共有しない

## 素材と実装
- 実際の画像デザインを制作し、64×64透明PNGを各形態について抽出・手動確認・減色した。
- Kotlinの `FeaturedPixelArt.kt` および `FeaturedCompanionArt.kt` に各形態を**固定の4bitパレット素材**として格納。生成ごとに画像が変わる仕組みは使わない。
- 64×64本編素材は全体の読みやすさを優先。ライゼル256×256は別途生成画像由来の高精細図鑑用PNGとして納品（現時点でアプリへの図鑑原画表示機能は未導入）。
- ルナ256×256は64×64を4倍拡大した確認画像であり、独立の高精細原画ではない。
- ドット絵は生成画像から編集・減色した素材であり、**手打ちで完全にピクセル単位から描き上げたものではない**。
- 既存の取り込みPNGがある個体はその素材を優先。名前・保存ID・属性・ステータスは変更しない。
- 全身Glyph表示はv3.4の0〜255輝度変換方式を継続。顔専用の置換処理は存在しない。

- ルナの高精細256×256描き下ろし、頭・尾・翼・装甲のパーツ分離と自然なモーション、全種族の高品質なアート素材追加は未実装。

## 判定基準
進化1・2・3が**同じ種族の成長**だと分かり、進化段階によって輪郭と配色が変化し、64×64で頭・胴・手足・尾などの重要部位が見えること。
