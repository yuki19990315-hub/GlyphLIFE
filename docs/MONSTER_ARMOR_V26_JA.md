# Monster Quest v2.6 — 素体固定＋AIアーマー提案

## 原則

ゲーム本編のマスターは**64×64の色付きドット絵**、図鑑や大きな画面での表示はニアレストネイバー4倍（256×256）。NothingのGlyphに送る段階で初めて13×13（物理137 LED）へ変換する。

**AIは元の生物の骨格やゲーム能力を変更しない。** AIに渡すのは種族・属性・骨格の種別・説明文で、返せるのは6か所の装備名だけ。実際のドット描画はゲーム側の安全な有限のカタログが行う。

## 素体（既存の10骨格）

BEAST（四足獣）、DRAGON（竜）、BIPED（二足）、GOLEM（巨像）、SERPENT（蛇）、AVIAN（鳥）、INSECTOID（昆虫）、AQUATIC（水棲）、MECHA（機械）、SPIRIT（霊体）。ライゼルの固有64×64素材も素体として利用できる。

## 装着スロットと解放段階

| スロット | 表示開始 | 主な部位 |
|---|---|---|
| HEAD | 進化1 | 頭部装甲・角・兜 |
| CORE | 進化1 | 胸部のコア・紋章 |
| TAIL | 進化1 | 尾・末端・追加パーツ |
| SHOULDER | 進化2 | 肩の大型装甲 |
| BACK | 進化2 | 背中の棘や背部装飾 |
| WING | 進化3 | 翼・追加肢 |

各スロットは「なし」「PLATE（重装甲）」「SPIKE（刃・棘）」「CRYSTAL（結晶）」「RUNE（紋章）」から選択。全骨格について装着位置を固定し、任意のAI出力からピクセル座標やプログラムを受け取らない。

進化が未到達の装備は選択・保存可能だが**その段階になるまで表示しない**。

## 属性プリセットとAI提案

手動操作と属性別プリセットは**完全無料・オフライン**で使える。

任意のAI提案ボタンは、画面下部で入力した**利用者自身のGemini APIキー（BYOK）**を使用する。JSONのキーはHEAD/CORE/TAIL/SHOULDER/BACK/WING、値はPLATE/SPIKE/CRYSTAL/RUNEに限定。6スロットが揃っていない・不明な名前・追加フィールドを含むJSONは拒否する。

AI提案は**画像生成ではなく、元の固定装備素材の組合せ提案**。API利用料金・利用枠はGoogleの提供条件に従う。アプリでの実API呼出しは未確認。

## 進化・融合の継承

- 進化では同じ素体と装備構成を維持し、装備の表示開始段階が到達したら対応するレイヤーを描画する。
- 合成は親Aの**HEAD/CORE/SHOULDER**、親Bの**TAIL/BACK/WING**を受け継ぐ。親に未装備のスロットは空欄のまま。合成後のプレビューは確定後と同じ絵になる。
- 64×64ネイティブアートのレイヤー合成は、戦闘・待機アニメ・画像書き出し・13×13 Glyph変換に共通適用する。

## データ保護と既存データ互換

`WildMonster.armorParts` は小さな文字列Mapで、既存セーブに存在しない場合は空Map。元のドット絵とユーザーが読み込んだPNGは上書きせず、表示時にだけ合成する。装備を全部外すと元の外観を復元できる。

新規の装備は**元画像にある色のみ**で描くため、新しい色が勝手に追加されて16色上限を超えることはない。AIに戦闘能力を決定する権限はない。

## 現段階の限界

- 装備素材は**手続きで描画するパーツ**。すべてがプロ絵師制作の独立スプライトという意味ではない。
- パーツごとの個別アニメーション、自由な部位の座標調整、独立PNG化、完成品のアートディレクション審査は未完了。
- AIモデルの実通信やスマホ実機のメモリ・UI確認は未検証。
