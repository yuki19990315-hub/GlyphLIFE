# AIモンスター工房 / 実装仕様

## ゴール
Monster Questの「召喚」タブに **AIで設定設計→任意のAI画像生成→64×64素材化→採用前プレビュー→図鑑登録** を実装する。既存の探索・育成・2体融合・図鑑・Glyph連携は維持。円や楕円の手続き描画は明示的に仮素材と扱う。

## マスター素材規格
- GBA風64×64、透過込み最大16色、不透明は最大15色。
- 透明か不透明のみ。描画1ピクセル単位、ぼかし・アンチエイリアスを禁止。
- 全身（角・翼・尾・脚を含む）が収まり、端に触れない。
- 3/4右向き、輪郭とピクセルクラスター、陰影をデザインする。既存IPをコピーしない。
- 画像の規格はGbaMonsterArtStandard.auditで判定。ただし**AIっぽさや解剖学の自然さは人が判断**。
- 256pxはnearest-neighbour整数倍表示。Glyph13×13は64×64から別途派生。

## 操作と安全性
1. 召喚タブでイメージを入力、AI画像生成の有無を選ぶ（画像生成は明示的な操作のみ）。
2. Geminiテキストモデルがメタデータを生成し、HPや攻撃はアプリが決める。
3. 画像生成ON時のみGemini画像モデルへ依頼し、端末内で64×64 PNGへ変換・色数検証。
4. 保存前のプレビューで採否を判断。規格外の画像候補は採用不可。
5. 不採用ならゲーム内資源・仲間・図鑑には変更なし。採用時だけ召喚結晶1個消費。
6. registerSummonで発行される**最終個体ID**でPNGを保存し、その後に図鑑と仲間を更新する。
7. 画像生成OFFの候補は手続き生成の**仮素材**であることを表示。

## 料金・情報
- Gemini APIキーはアプリ起動中だけメモリ保持。外部へ送信するデータは生成指示と、写真から生成を明示的に選択した場合の縮小画像。
- 画像モデルgemini-3.1-flash-imageは有料の場合があり、候補の不採用でもAPI料金は戻らない。
- 実機API疎通・実機見た目は未検証。CIビルド成功は実機成功を意味しない。

## 未実装・次段階
- 親2体の画像をAIに参照させる融合デザイン、進化3段階の生成一貫性、候補の複数比較、インペイント、目視品質の完全自動評価。
- これらは既存融合ゲームルールとは別であり、本仕様に書かれていても実装済みと扱わない。

## ピクセルラボ風の候補選択（追加）
- NEXT ADVENTURE の公開ガイドで確認できた **文章指定 → 画像生成 → 再生成 → 採用して設定** という**操作フローのみ**を参考にする。非公開APIやデザイン・固有素材は複製しない。
- 最初の候補をプレビューし、必要なら「別案への指示（最大100文字）」を入力して追加生成。**1セッション最大4画像**、最新候補を表示する。
- 全候補を一時的にメモリに保持し、前の候補にも戻って選べる。採用時は選択中の64×64 PNGだけ保存する。
- 未採用の候補は図鑑に入れない。修正指示による「別案生成」は**新規生成**であり、既存画像の局所修正（インペイント）ではない。
- 画像モデル呼び出しはユーザーが「AI画像を生成」「別案をAI生成」を押した時のみ。呼び出しごとに課金の可能性がある。
- 各候補のサイズ・色数・透過・端接触を審査し、規格外の場合はその候補の採用を不可にする。ただし前の合格候補は選択可能。
- 新たな導線は「召喚」画面の既存AIモンスター工房内で動作し、別途ブラウザのログインやチケット販売機能は模倣しない。
