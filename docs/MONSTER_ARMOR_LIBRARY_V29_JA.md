# Monster Quest v2.9 — AI装備画像パーツを再利用できる保管庫

## 目標
有料の画像生成APIで作った角・翼・胸コアなどの装備パーツを、1体に付けた後も他の個体で再利用する。同じ画像を再度AIへ生成依頼する必要はない。

## 操作
1. 一度でもAIで画像を生成して装着、または透明PNGを画像として取り込む。
2. 「モンスター研究所」→「捕獲図鑑・合成」→仲間A選択→「装備を編集」。
3. 目的の部位で「保存済みパーツを使う」。既存PNGが8個ずつ一覧表示される。
4. 装着候補を選ぶと、**既存の確認ダイアログ**で64px完成予想を表示。承認するまでは装備状態を更新しない。
5. 承認時、パーツ画像IDを個体の`customArmorParts`へ保存。画像ファイル本体はコピーせず、既存ファイルを参照する。新しい装着位置の調整値は初期状態となる。
6. 必要に応じて個体ごとに位置（±12px）と大きさ（50～150%）を調整。ほかの個体の装着状態は変わらない。

## 保存形式と安全性
- PNGはアプリ専用ディレクトリ`monster_armor_layers_v1`にUUID.png形式で保存。ファイルを外部ネットワークへ公開しない。
- 一覧には正規形式のUUID.png・100～3,500,000バイトの通常ファイルのみ表示。部分書き込みファイル、文字列パス、壊れたサイズなどは除外。
- 新しい画像の生成・取り込み直後の仮画像は、キャンセル時に削除する。
- **既存の保管庫画像を選び直した場合はその画像を削除しない**。モンスター同士で参照を共有するため、別個体の画像を破壊しない。
- 既存PNGが消えた場合は新規装着を拒否。旧セーブは読み込み可能な画像がない場合でも通常素体を使って継続できる。
- 同一画像IDを別部位へ再利用可能。外観に合わせて自動的にサイズ・位置・使用色を調整する。
- 一覧は新しいものから最大500件・1ページ8件。500を超える古いアイテムの絞り込み機能や一括削除は未実装。

## 進化・融合・Glyph
- 進化時は元の画像IDを保ち、スロットの進化条件まで表示を保留。
- 融合時は親Aの頭・胸・肩、親Bの尾・背・翼を共有IDのまま継承。両親の画像ファイルは破棄しない。
- 正本64×64、256pxのニアレスト拡大、Glyphの13×13射影は共通`spriteFor`パイプライン経由。
- 追加AI生成は一切起きない。既存パーツの読み込みのみオフライン実行。

## 検証
- JVMテスト：不正なファイル名・拡張子・不正容量を除外。重複ID・同時刻並び・ページ区切りを検証。
- JVMテスト：1つの同一パーツを2個体に同時使用しても元PNG画素が変わらず、融合でも参照が維持されることを検証。
- Android APKビルドと他ゲーム機能への回帰はGitHub Actionsで確認する。
- 実機操作・外部Gemini画像生成の成功と品質は未確認。
