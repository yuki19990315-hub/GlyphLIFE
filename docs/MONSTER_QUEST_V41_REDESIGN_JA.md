# Monster Quest v4.1 — UI/戦闘/モンスター表示の全面調整

## 修正理由と原因
- v4.0はイメージ図と異なり、実際の画面は単純な素材・説明文中心だった。
- 探検シーン左側にプレイヤーの人型仮スプライトがあり、相棒モンスターが主役になっていなかった。
- 敵も味方も基本的に同じ向きで描画されていた。
- 連打中は3タップごとに敵反撃、ボスもタップ数で攻撃が発動するため、連打するほど敵まで素早く攻撃していた。
- 汎用モンスターは楕円や幾何学を重ねた手続き描画で、以前作った10系統のデザイン資料がゲームに反映されていなかった。

## 実装
1. **味方＝左・右向き／敵＝右・左向き**。人型主人公を削除し、現在の相棒モンスターを `MonsterArtworkView` から描画。敵画像を水平反転。
2. **新しい時間制戦闘**：タップはプレイヤーが一撃を加えるだけ。敵は独立したクロックで通常2700ms、ボス3800ms、ボス半HP以下2600msの間隔で反撃。画面に残り秒数、HIT数、回避方向を表示。ホームなどへ移動した場合は戦闘を停止。
3. **ボス独自性**：左右の攻撃予告→反対側に回避→3タップだけ弱点3倍。攻撃タップだけではボスの攻撃時刻は早まらない。
4. **モンスター固定素材**：以前の「10系統×進化3段階」デザイン資料を元に、30種類を透明背景・64×64・透過込み最大16色に変換し本編へ導入。元のライゼル／ルナの専用素材は維持。古い楕円ベース生成は通常ゲームプレイで使わない。任意のデザイン選択では個体ごとに小さい角や装飾を安定的に変化させる。
5. **素材ZIP**：`monsterquest/art_sources/curated_monsters_v41.zip` に30 PNG＋確認用一覧＋メタデータを保存。Kotlinランタイムでは `CuratedMonsterArt.kt` の圧縮データを使用。ゲーム中に追加のネットワーク通信はない。
6. **新UI**：ホームは森を背景に相棒、下部6メニュー（パーティ・装備・アイテム・図鑑・進化・プロフィール）。探検は金色フレーム、左右HP、広い戦闘シーン、連打ボタン、捕獲・回復。召喚は紫のクリスタル祭壇をピクセルCanvasで描画。下タブはホーム・探検・召喚・？（未開放）。
7. **背景**：晴れた森・滝と城、月夜の遺跡、光る結晶洞窟の3テーマ。ランダムではなくフロア帯で切替し、歩数に応じて背景が動く。
8. **連打パフォーマンス**：タップ中のセーブは5HIT単位にまとめ、敵の攻撃やフェーズ変更は保存。UIの戦闘タイマーは100ms間隔で進み、タップ操作とは切り離す。

## 旧データの扱い
ユーザーの「旧データは上書きしてよい」の許可に基づき、v4.1では新規セーブ領域 `monsterquest_v41_clean` からスタート。旧 `monsterquest_v1` 領域は物理的には消さないが、新アプリの通常ロード対象外のため、**探索記録・捕獲・編成・図鑑・結晶・装備は初期状態から始まる**。旧画像の保存ファイルも残るが、旧IDをロードしないため表示に使用しない。この判断は再インストール・旧APKへのロールバック可否を保証しない。

## 確認項目
- `TapAdventureTest`：40タップを連続実行しても敵HPが減るだけで、プレイヤーHPも敵の攻撃タイマーも変化しない。時間経過だけで敵が攻撃、ボス回避・弱点・死亡時リスタートも確認。
- `CuratedMonsterArtTest`：10体型3段階の64px、最大16色、透明背景、全身マージン、進化差分、Glyph全身への輝度投影を確認。
- CIのAndroid/Glyph SDKコンパイルが成功しても、実機での描画・タップ連打レスポンス・GlyphのLED表示は別途検証が必要。

## 限界
- 元デザインは生成されたイラストから編集・減色したドット素材であり、全てを1px単位で手描きしてはいない。
- 10系統×3形態を基礎とするため、全てのAI生成種族が独自描き下ろしの外見になるわけではない。AI画像を取り込んだ場合はそちらの個体画像が優先される。
- 画面デザインは以前のイメージ図を**参考にCompose/Canvasで新規実装**したもので、元画像とピクセル単位で完全一致するわけではない。
- タイマーは探索タブを表示している間だけ進む。攻撃前に独立した予告を表示するが、実機の感触によって速度調整が必要な場合がある。
