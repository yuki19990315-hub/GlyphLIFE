# Monster Quest v2 — 高画質ドット絵ファースト

更新: 2026-11-12。対象: `monsterquest/` の実装。ゲーム本編の**画像の正本は64×64カラードット絵**であり、Glyph 13×13は表示するときだけ生成する派生データ。

## 1. 画像パイプライン

```text
名前・属性・体型・モチーフ・段階（任意でGeminiテキスト生成）
      ├─ オフラインの完全オリジナル64×64ドット絵（10体型×7属性）
      └─ 任意の有料AI画像生成 / ユーザー所持画像
                    ↓
             64×64 RGB/透明・最大16色へ減色
                    ↓
       ネイティブPNG正本（個体ID＋進化段階）
              ├─ 本編戦闘：64×64を256×256にニアレスト拡大
              ├─ 図鑑：256×256表示／PNG書き出し
              ├─ 64×64 PNG書き出し
              └─ Glyph使用時のみ64→13×13の2値変換→物理137LEDマスク
                                        ↓
                                 GlyphLIFEへ共有
                               （既存アート上書き確認）
```

256×256は64×64から4倍に**ニアレスト拡大した表示・ファイル**であり、画素レベルの新しい描き込みが増えるわけではない。本当の256×256独立画素の手描き原画は将来の拡張。

### データ保護・互換
- `WildMonster`に bodyType / stage / lineage / motifPrimary / motifSecondary を追加し、旧セーブにデフォルト値を与える。既存の個体UUID、能力値、捕獲データは維持する。
- 64px素材は`monster_art_v1/<uuid>-s<stage>.png`で個体・段階ごとに端末内保存。旧`<uuid>.jpg`と旧`<uuid>.png`は削除せず、幼体の画像として読み取れる。
- AI/外部画像はユーザーが明示的に選択した時だけ64px PNGへ変換。余計な権限で端末全体の写真を閲覧しない。
- 画像に一様な背景色があれば端からの連結色領域を自動除去する。背景が複雑な場合は完全透過を保証できず、イラストの見た目が損なわれることがある。
- PNGエクスポートはAndroid MediaStoreの`Pictures/MonsterQuest`へ保存。
- 端末実機のレンダリング、SDK転送、API実通信は未検証。

## 2. オリジナルのデザイン文法

参照すべき一般的な長所は「一目で認識できるシルエット」「属性と配色の一貫性」「進化で核となる形状を保持」「ドットクラスターの読ませ方」「迫力ある強化部品」。**ポケモン・デジモン・Coromon・Monster Sanctuary等の素材やキャラクターを取り込んだ独自モデルの再学習は行っていない**。ユーザーが所有していないキャラ画像やデータセットを無断収集して学習する機能は実装していない。

### 10種類の体型
| 体型 | 実装されたシルエット・意匠 |
|---|---|
|BEAST|四足、頭部・鼻、牙、角、大きな尾|
|DRAGON|角、翼、強い肩と尾、鉤爪|
|BIPED|二足、胴と独立した腕、脚部装甲|
|GOLEM|大きい矩形胴体、岩・板状腕、発光コア|
|SERPENT|複数の連結した胴体節、角・首|
|AVIAN|広い左右翼、嘴、長い尾羽|
|INSECTOID|複数の脚、触角、複眼、硬質体節|
|AQUATIC|流線形の体、ヒレ、尾鰭|
|MECHA|対称装甲、メカ脚、センサー発光|
|SPIRIT|浮遊する胴、尾状のエネルギー、異形の角|

各体型の輪郭と発光箇所は64pxマスターで描画。オフライン生成は単純な手続きアートであり、有名ゲームの手描きアーティスト品質を保証するものではない。

### 属性と配色
| 属性 | 基調 |
|---|---|
|火|深赤・朱・黄金色|
|水|紺・青緑・氷白|
|草|深緑・葉緑・黄緑|
|雷|黒紫・青紫・黄色発光|
|光|灰紫・金・乳白|
|闇|黒紫・赤紫・妖光|
|無|石色・鋼色・骨白|

オフライン描画の基調パレットは5色。AI生成画像/持込画像は最大16色の候補へ減色する（目標の12～16色を使い切ることは保証しない）。透過色は別管理。

## 3. 進化と融合
- 進化は3段階。冒険で2体撃破すると第2段階、4体撃破すると第3段階へ進化可能。
- 同じ個体ID・体型・属性・モチーフを維持して角・肩・発光・翼飾り等が増える。段階ごとのオリジナルPNGが無ければ、その段階用手続き64pxが出る。
- 融合は親の**主側体型・顔の骨格**を残し、**副側のモチーフ**を翼・尾・装甲などの追加シルエットに変換。融合の属性は既存のFusionRulesに従う。素材2匹は消費する。
- バトル能力値・報酬はAI画像や見た目で決めない。
- 進化の第2・第3段階は見た目の連続性を重視するが、AIに任意生成した画像の一貫性は実機で未検証。

## 4. 高精細AIの安全な使い方
- Gemini画像生成のプロンプトは「1体のオリジナルなドット絵」「正方形」「単色マゼンタ背景」「硬いドットの輪郭」「最大16色へ変換する前提」を指示する。
- 画像APIは明示的なボタン操作・ユーザー入力のAPIキーを前提とする。暗黙の連続課金は行わない。
- Gemini 3.1 Flash Imageは2026-11-12確認時点で無料枠なし、1K出力画像約$0.067/枚＋入力料金。料金と生成モデルの提供可否はGoogle公式で再確認する。
- Googleから返った1K画像は本物の64px手描き原画ではない。端末内で64×64にピクセル化、減色した**ゲーム用ネイティブ素材**にする。生成AIの完成品質と著作権上の独自性には別途レビューが必要。
- 他社ゲームのキャラの直接再現、データセットの無断収集、再学習は行わない。

## 5. Glyph変換ルール
- 13×13 = 169論理マス、うち32マスはLEDなし。背面で有効な137マスだけ点灯可。
- 64px画素の局所被覆率33%以上で点灯。明るいアクセントを含む場合は13%以上でも点灯させ、細い角や目の重要情報の消失を抑える。
- 主体の輪郭・目・角・羽が見えるよう、13pxで必要ならGlyph Creatorで修正する。Glyphデータを本編へ再拡大して正本化しない。
- Monster Questが送る`glyph-life-animation` JSON v1をGlyphLIFEが受信。ユーザーの明示確認後だけCreatorの現在の絵に適用する。
- 正しい転送・見栄え・LED更新はNothing Phone (4a) Pro実機で確認が必要。
